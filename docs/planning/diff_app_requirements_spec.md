# diff-app 要件定義・基本仕様書 完成版 v1.0

## 1. 概要

本アプリケーションは、2つのディレクトリまたは任意の2ファイルを比較し、差分の確認・ファイル単位同期・履歴管理・復元を行うためのTauriベースのデスクトップ向け差分比較・同期支援アプリケーションである。

Windows環境では、通常のWindowsファイルシステム上のフォルダに加えて、WSL2上のLinuxファイルシステム配下のフォルダも比較対象・同期対象として扱えることを要件とする。

主な利用目的は、複数フォルダ間に存在する類似ファイルの差分確認、変更内容の片方向反映、同期操作の履歴追跡、および誤操作時の復元である。

初期リリースでは、安全性と実装可能性を優先し、ファイル単位同期を必須機能とする。差分ブロック単位同期は仕様上は定義するが、初期必須機能からは外し、後続リリースで実装する。

---

## 2. 想定ユーザー

- ソフトウェア開発者
- 設定ファイルやドキュメントを複数環境間で比較・同期する利用者
- ディレクトリ間の差分を確認して、必要な変更だけを手動で取り込みたい利用者

## 3. 用語定義

| 用語 | 意味 |
|---|---|
| 左側ディレクトリ | 比較対象として選択された一方のディレクトリ |
| 右側ディレクトリ | 比較対象として選択されたもう一方のディレクトリ |
| 一括diff | 2つのディレクトリ内でファイル名または相対パスが一致するファイルをまとめて比較する処理 |
| 指定diff | 任意に選択した2つのファイルを比較する処理 |
| 同期 | 差分またはファイル全体を片方からもう片方へ反映する処理 |
| 差分単位同期 | 差分表示画面で選択した差分ブロックだけを反映する処理 |
| ファイル単位同期 | ファイル全体を片方の内容で上書きする処理 |
| 履歴 | 同期操作前後の状態をGitコミットとして記録したもの |
| 復元 | 過去の同期操作前の状態に戻すこと |

## 6. 一括diffモード仕様

### 6.1 概要

一括diffモードでは、ユーザーが選択した2つのディレクトリを並べて表示し、相対パスが一致するファイルを標準の比較対象として抽出する。オプション設定により、ファイル名のみ一致するファイルも比較対象にできる。

比較結果は一覧表示され、ユーザーが一覧からファイルを選択すると、そのファイルの差分詳細を確認できる。

### 6.2 入力

| 項目 | 内容 |
|---|---|
| 左側ディレクトリ | 比較対象ディレクトリA |
| 右側ディレクトリ | 比較対象ディレクトリB |
| 比較方式 | 標準は相対パス一致。オプションでファイル名一致を利用可能 |
| 除外ルール | 左右ディレクトリ配下の `.gitignore` を参照して除外する |
| 対象拡張子 | 任意。未指定の場合はすべてのテキストファイル |
| 対象パス種別 | Windows通常パス、UNCパス、WSL2配下パスを対象にできる |

### 6.2.1 `.gitignore` による除外ルール

一括diffモードでは、比較対象ディレクトリ配下の `.gitignore` を参照し、Gitで無視されるファイル・ディレクトリを比較対象から除外する。

基本ルールは以下とする。

- 左側ディレクトリでは、左側ディレクトリ配下の `.gitignore` を参照する
- 右側ディレクトリでは、右側ディレクトリ配下の `.gitignore` を参照する
- `.git` ディレクトリは常に除外する
- `.gitignore` 自体は比較対象に含める
- `.gitignore` が存在しない場合は、`.git` などのアプリ既定の最低限の除外ルールのみ適用する
- 除外されたファイルは、比較結果一覧には原則表示しない

左右の `.gitignore` は独立して適用する。注意点として、左右で `.gitignore` の内容が異なる場合、片方では除外され、もう片方では比較対象になる可能性がある。この場合は、ユーザーの混乱を避けるため、比較前に「左右で除外ルールが異なる」ことを警告表示できるようにする。

### 6.3 ファイル照合ルール

初期仕様では、以下の優先順で照合する。

1. 相対パスが一致するファイルを同一ファイルとして扱う
2. オプション設定により、ファイル名のみ一致するファイルも比較対象にできる
3. 同一ファイル名が複数存在する場合は、曖昧な一致として一覧に警告表示する

#### 例

| 左側 | 右側 | 判定 |
|---|---|---|
| src/app.ts | src/app.ts | 相対パス一致 |
| src/app.ts | backup/app.ts | ファイル名一致。ただし相対パス不一致 |
| src/app.ts | src/main.ts | 不一致 |

### 6.4 比較結果一覧

一覧には以下を表示する。

| 項目 | 内容 |
|---|---|
| ファイル名 | 比較対象ファイル名 |
| 左側パス | 左側ディレクトリ内の相対パス |
| 右側パス | 右側ディレクトリ内の相対パス |
| 状態 | 同一、変更あり、左のみ、右のみ、比較不可 |
| 差分行数 | 追加・削除・変更の概算行数 |
| 最終更新日時 | 左右ファイルの更新日時 |
| 同期状態 | 未同期、同期済み、競合、復元済み |

### 6.5 状態分類

| 状態 | 意味 |
|---|---|
| 同一 | 内容に差分がない |
| 変更あり | 内容に差分がある |
| 左のみ | 左側にのみ存在する。左→右の作成同期が可能 |
| 右のみ | 右側にのみ存在する。右→左の作成同期が可能 |
| 比較不可 | バイナリ、権限不足、文字コード不明など |
| 曖昧一致 | ファイル名一致だが候補が複数存在する |

### 6.6 操作

- ディレクトリ選択
- 比較実行
- 比較結果の再読み込み
- 状態によるフィルタ
- ファイル名検索
- 差分詳細表示
- 左から右へ同期
- 右から左へ同期
- 比較対象から除外

### 6.7 Windows / WSL2 フォルダ対応

Windows環境では、以下のパスを比較対象・同期対象として扱えること。

| パス種別 | 例 | 扱い |
|---|---|---|
| Windows通常パス | `C:\Users\user\project` | 通常のローカルフォルダとして扱う |
| UNCパス | `\server\share\project` | 権限がある場合は対象にできる |
| WSL2配下パス | `\wsl$\Ubuntu\home\user\project` | WSL2上のLinuxファイルシステムとして対象にできる |

WSL2配下フォルダを扱う場合の基本方針は以下とする。

- Windows側のTauriアプリから `\wsl$\<DistributionName>\...` 形式のパスを選択できること
- WSL2配下ファイルも、通常のファイルと同様に一覧表示・diff表示・ファイル単位同期・作成同期の対象にできること
- `.gitignore` はWSL2配下の対象ディレクトリに存在するものを参照すること
- WSL2配下のファイルでは、Linuxの権限・シンボリックリンク・大文字小文字の区別に注意すること
- WindowsパスとWSL2パスを左右に混在させた比較も許可すること

制約として、WSL2配下へのアクセスはWindows通常フォルダよりI/O性能が低下する可能性がある。そのため、大量ファイル比較時は警告または進捗表示を行う。

## 7. 指定diffモード仕様

### 7.1 概要

指定diffモードでは、ファイル名や配置場所が異なる2ファイルをユーザーが明示的に選択し、内容の差分を比較する。

### 7.2 入力

| 項目 | 内容 |
|---|---|
| 左側ファイル | 比較対象ファイルA |
| 右側ファイル | 比較対象ファイルB |
| 文字コード | 初期リリースではUTF-8のみ対応。将来的に自動判定やShift_JIS等へ拡張 |
| 改行コード扱い | 表示上は差分として扱わず、同期時は同期先ファイルの既存改行コードを維持 |
| 空白差分 | 初期設定では差分として扱う。オプションで無視可能 |
| 対象パス種別 | Windows通常パス、UNCパス、WSL2配下パスを対象にできる |

### 7.3 操作

- 左側ファイル選択
- 右側ファイル選択
- diff実行
- 差分詳細表示
- ファイル単位同期
- 選択差分の左から右への適用（後続リリース候補）
- 選択差分の右から左への適用（後続リリース候補）

### 7.4 一括diffモードとの差異

| 項目 | 一括diffモード | 指定diffモード |
|---|---|---|
| 比較対象 | ディレクトリ内の複数ファイル | 任意の2ファイル |
| ファイル名一致 | 原則必要 | 不要 |
| 一覧表示 | あり | 原則なし |
| 同期 | 複数ファイル対象 | 選択ファイル対象 |

## 8. 差分詳細表示仕様

### 8.1 表示形式

差分詳細画面では、左右2ペイン形式で差分を表示する。

| 表示項目 | 内容 |
|---|---|
| 左ペイン | 左側ファイル内容 |
| 右ペイン | 右側ファイル内容 |
| 行番号 | 左右それぞれの行番号 |
| 差分ハイライト | 追加、削除、変更箇所を視覚表示 |
| 差分ブロック | 変更単位のまとまり |
| 同期操作ボタン | 差分単位で左→右、右→左を実行 |

### 8.2 差分単位

差分は、以下の単位で扱う。

- 行単位
- 連続した変更行をまとめたブロック単位

初期リリースでは、差分ブロック単位同期は必須機能に含めない。まずファイル単位同期を安定実装し、差分ブロック単位同期は後続リリース候補とする。行単位の細かい同期は、操作ミスやコンフリクトが増えるためさらに後続拡張とする。

### 8.3 表示オプション

- 空白差分を無視（初期設定は無視しない）
- 改行コード差分を表示上は無視
- 大文字小文字差分を無視
- 行内差分を強調表示
- 折り返し表示
- 差分のみ表示
- 変更前後の周辺行数を指定

## 9. 同期モード仕様

### 9.1 概要

同期モードでは、差分詳細画面または比較結果一覧から、ファイル全体を片方へ反映する。差分ブロック単位の反映は後続リリース候補として扱う。

同期操作はGitによって履歴化し、後から確認・復元できるようにする。

### 9.2 同期方式

| 同期方式 | 内容 |
|---|---|
| ファイル単位同期 | 一方のファイル内容で他方を完全に上書きする。初期リリースの必須機能 |
| 作成同期 | 片側にのみ存在するファイルを、反対側へ新規作成する。初期リリースの対象 |
| 差分ブロック単位同期 | 選択した差分ブロックのみを反映する。後続リリース候補 |

### 9.3 同期方向

| 方向 | 内容 |
|---|---|
| 左 → 右 | 左側の内容を右側へ反映 |
| 右 → 左 | 右側の内容を左側へ反映 |

### 9.4 同期前確認

同期前に以下を表示する。

- 同期対象ファイル
- 同期方向
- 同期方式
- 変更される行数
- 作成または上書きされる内容の概要
- Gitコミットメッセージ案
- 復元可能性の説明

### 9.5 同期実行条件

同期実行前に以下を確認する。

- 対象ファイルが存在すること。ただし、片側のみファイルの作成同期では同期先ファイルが存在しなくてもよい
- 同期先ディレクトリまたは対象ファイルに書き込み権限があること
- 同期前からファイルが外部変更されていないこと
- Git履歴保存に成功できる状態であること
- バイナリファイルの場合、内容比較は不可とし、初期リリースでは同期対象外とする

### 9.6 外部変更検知

比較後に対象ファイルが外部プロセスで変更されていた場合、同期実行を停止し、再比較を求める。

判定には以下を利用する。

- 最終更新日時
- ファイルサイズ
- 必要に応じてファイルハッシュ

## 10. Git履歴管理仕様

### 10.1 基本方針

同期操作の履歴はGitコミットとして保存する。

ただし、ユーザーが選択した任意ディレクトリが既存のGitリポジトリである可能性があるため、履歴管理方式は慎重に設計する必要がある。

### 10.2 履歴管理方式の候補

| 方式 | 内容 | メリット | リスク |
|---|---|---|---|
| 対象ディレクトリ内の既存Gitを使う | 対象フォルダがGit管理下ならそのままコミットする | 実体と履歴が一致する | ユーザーの既存リポジトリを汚す可能性がある |
| アプリ専用Git管理領域を使う | アプリの管理フォルダに同期対象のスナップショットを保存してコミットする | ユーザーの既存Gitを汚さない | 実ファイルとの差分復元設計が必要 |
| 対象ディレクトリに隠しGitを作る | .diff-app-history などで管理する | 対象ごとに履歴を持てる | ディレクトリ構造が複雑化する |

### 10.3 推奨方針

初期仕様では、アプリ専用Git管理領域を使う方式で確定する。

理由は以下の通り。

- ユーザーの既存Gitリポジトリを壊さない
- 任意ディレクトリでも履歴を残せる
- 同期アプリとしての責務をアプリ内に閉じられる
- 復元操作をアプリ側で制御しやすい

Windows環境でWSL2配下フォルダを扱う場合も、履歴はアプリ専用Git管理領域に保存する。対象フォルダがWSL2上のGitリポジトリであっても、その既存Gitリポジトリには自動コミットしない。

### 10.4 履歴保存タイミング

同期実行時には、以下の順序で履歴を保存する。

1. 同期前の対象ファイル状態をスナップショット保存
2. 同期処理を実行
3. 同期後の対象ファイル状態をスナップショット保存
4. 同期メタデータを保存
5. Gitコミットを作成

### 10.5 コミットメッセージ形式

```text
sync: apply diff from left to right

Mode: bulk-diff | specified-diff
Sync type: hunk | file
Source: <source path>
Target: <target path>
Timestamp: <ISO datetime>
```

### 10.6 履歴メタデータ

各同期操作について、以下を保存する。

| 項目 | 内容 |
|---|---|
| 操作ID | 同期操作を識別するID |
| 実行日時 | 同期実行日時 |
| モード | 一括diff、指定diff |
| 同期方式 | 差分単位、ファイル単位 |
| 同期方向 | 左→右、右→左 |
| ソースパス | 反映元ファイル |
| ターゲットパス | 反映先ファイル |
| 同期前ハッシュ | 変更前ファイルのハッシュ |
| 同期後ハッシュ | 変更後ファイルのハッシュ |
| コミットID | GitコミットID |
| 結果 | 成功、失敗、復元済み |

### 10.7 復元仕様

復元は、同期操作単位で行う。

復元では、指定した履歴の同期前状態を対象ファイルに戻す。

復元前には以下を確認する。

- 現在のファイルが履歴上の同期後状態と一致しているか
- 一致しない場合、外部変更ありとして警告する
- 強制復元を許可するかどうかは設定で制御する

初期仕様では、安全性を優先し、外部変更がある場合は強制復元を許可しない。

WSL2配下ファイルの復元では、Windows側から書き込み可能であることを確認する。権限不足、WSLディストリビューション停止、またはパス解決不可の場合は復元を中止し、ユーザーに再試行またはWSL起動を促す。

## 12. 主要ユースケース

### 12.1 一括diffを実行する

1. ユーザーは一括diffモードを選択する
2. 左側ディレクトリを選択する
3. 右側ディレクトリを選択する
4. 比較方式と除外条件を設定する
5. 比較を実行する
6. アプリは一致ファイルを抽出する
7. アプリは各ファイルのdiffを実行する
8. アプリは比較結果一覧を表示する
9. ユーザーは一覧からファイルを選択する
10. アプリは差分詳細を表示する

### 12.2 ファイル名が異なる2ファイルを比較する

1. ユーザーは指定diffモードを選択する
2. 左側ファイルを選択する
3. 右側ファイルを選択する
4. 比較を実行する
5. アプリは差分詳細を表示する

### 12.3 選択差分を片方へ適用する（後続リリース候補）

1. ユーザーは差分詳細画面で差分ブロックを選択する
2. ユーザーは同期方向を選択する
3. アプリは同期確認画面を表示する
4. ユーザーは内容を確認して同期を実行する
5. アプリは同期前状態を履歴に保存する
6. アプリは選択差分を対象ファイルへ適用する
7. アプリは同期後状態を履歴に保存する
8. アプリはGitコミットを作成する
9. アプリは同期結果を表示する

初期リリースでは本ユースケースは必須対象外とし、ファイル単位同期を優先する。

### 12.4 ファイルごと同期する

1. ユーザーは比較結果一覧または差分詳細画面でファイル単位同期を選択する
2. ユーザーは同期方向を選択する
3. アプリは作成または上書き内容を確認表示する
4. ユーザーは同期を実行する
5. アプリは対象ファイルを作成または上書きする
6. アプリは同期履歴をGitコミットする

片側にのみ存在するファイルは、存在しない側へ新規作成できる。ただし、削除同期は初期リリースでは行わない。

### 12.5 同期を元に戻す

1. ユーザーは履歴画面を開く
2. ユーザーは戻したい同期履歴を選択する
3. アプリは復元対象と復元内容を表示する
4. アプリは現在ファイルの外部変更有無を確認する
5. 問題がなければ同期前状態へ復元する
6. アプリは復元操作も履歴として記録する

| ケース | 挙動 |

- 同期前に必ず確認画面を表示する
- 同期前後の状態を履歴保存する

- 同期方向が誤解されないこと

- Git以外の履歴管理方式も差し替え可能にすること

## 15. UI設計上の注意点

### 15.1 同期方向の誤操作防止

同期方向は、ボタン文言だけでなく視覚的にも明確にする。

例：

- `左の内容を右へ適用`
- `右の内容を左へ適用`
- `右ファイルを上書きします`
- `左ファイルを上書きします`

単に `→` や `←` だけで表現しない。

### 15.2 ファイル単位同期の危険性

ファイル単位同期は上書き操作であるため、差分単位同期より強い確認を行う。

表示すべき内容：

- 上書きされるファイル
- 失われる変更の概要
- 復元可能であること
- ただし外部変更がある場合は復元できない可能性があること

### 15.3 Git履歴の見せ方

GitのコミットIDをそのまま前面に出すのではなく、ユーザーには操作履歴として表示する。

例：

| 表示 | 内部情報 |
|---|---|
| 2026-05-24 10:30 app.ts を左から右へ同期 | commitId: abc123 |

## 16. 技術設計上の論点

### 16.1 Git履歴をどこに作るか

最重要論点である。

任意ディレクトリに対して自動的にGitコミットする設計は危険である。既存プロジェクトのGit履歴を汚す可能性があり、利用者の期待にも反する可能性がある。

初期設計では、アプリ専用の履歴管理領域にスナップショットを保存し、その領域をGit管理する方針が安全である。

### 16.2 差分単位同期の実装難易度

差分単位同期は、単純なコピーではなくパッチ適用に近い処理になる。

以下の問題がある。

- 比較後にファイルが変更されるとパッチが当たらない
- 近接する差分ブロックの扱いが難しい
- 改行コードや文字コードの扱いで失敗する可能性がある
- 部分適用後に構文的に壊れる可能性がある

したがって、初期実装ではブロック単位同期を基本とし、適用前にハッシュ確認を行う。

### 16.3 バイナリファイル

初期仕様では、バイナリファイルは一覧には表示するが、内容比較は不可とする。

理由は以下の通り。

- 差分表示方式がテキストと異なる
- 部分同期が困難
- 誤った上書き時の被害が大きい

### 16.4 Windows / WSL2 パス対応

Windows版では、WSL2配下フォルダを比較・同期対象にできることを要件とする。

主な実装論点は以下である。

- Windows通常パス、UNCパス、WSL2パスを内部的に区別する
- `\wsl$\<DistributionName>\...` 形式のパスを選択・保存できるようにする
- WSL2配下ではLinuxファイルシステムの大文字小文字区別を前提にする
- シンボリックリンクの扱いを明確化する
- WSL2配下アクセス時はI/O遅延を前提に、非同期処理・進捗表示・キャンセル機能を用意する
- Git履歴管理は既存WSL2側リポジトリではなく、アプリ専用Git管理領域に保存する

初期リリースでは、WSL2配下パスのシンボリックリンクは追跡しない方針とする。シンボリックリンクを検出した場合は、比較対象外または比較不可として表示する。

## 18. 受け入れ条件

- 2つのディレクトリを選択できる

- 差分あり、同一、左のみ、右のみ、比較不可を一覧表示できる
- 一覧からファイルを選択すると差分詳細を表示できる
- Windows環境で `\wsl$\<DistributionName>\...` 配下のディレクトリを選択して比較できる
- Windows通常フォルダとWSL2配下フォルダを左右に混在させて比較できる

### 18.2 指定diff

- 異なるファイル名の2ファイルを選択できる
- 選択した2ファイルの差分を表示できる

### 18.3 同期

- 差分詳細画面から同期方向を選択できる
- ファイル単位で左から右へ同期できる
- ファイル単位で右から左へ同期できる
- 左のみファイルを右側へ新規作成できる
- 右のみファイルを左側へ新規作成できる
- 削除同期は実行されない
- 同期前に確認画面を表示できる
- 同期後に履歴が保存される

- 同期履歴を一覧表示できる
- 同期前後の対象ファイルを確認できる
- 同期操作単位で過去の同期前状態へ復元できる
- 復元操作も履歴に残る

### 18.5 安全性

- 同期前に対象ファイルが外部変更されていた場合、同期を停止する
- 書き込み権限がないファイルへの同期は実行されない
- Git履歴保存に失敗した場合、ユーザーにエラーを表示する

## 21. 判断メモ

現時点の仕様で最も注意すべき点は、「同期」と「Git履歴」を安易に結合しないことである。

Gitを使えば履歴は残せるが、既存リポジトリに自動コミットする設計は利用者にとって危険であり、予期しない副作用を生む。したがって、初期設計ではアプリ専用の履歴領域でGit管理し、実ファイルへの同期操作とは明確に分離するのが妥当である。

また、差分ブロック単位同期は便利だが、実装難易度と誤適用リスクが高い。初期リリースでは、まずファイル単位同期、片側のみファイルの作成同期、安全な履歴管理、同期操作単位の復元を完成させ、その後に差分ブロック単位同期へ進む方が現実的である。

本仕様では、削除同期と既存Gitリポジトリへの自動コミットは初期リリース対象外とする。これは、誤操作時の被害が大きく、利用者の既存作業環境に副作用を与える可能性が高いためである。

Windows環境ではWSL2配下フォルダも比較・同期対象に含める。ただし、WSL2配下はWindows通常フォルダと比べてI/O性能、権限、シンボリックリンク、大文字小文字区別の扱いが異なるため、通常パスと同一視しない。内部的にはパス種別を保持し、エラー表示、進捗表示、同期前確認を明確に分ける必要がある。
