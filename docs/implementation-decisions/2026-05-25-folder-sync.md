## 依頼と参照元の要約

ツリー表示でフォルダ配下の差分をまとめて左から右、または右から左へ反映できるようにする。同期は上書き/作成のみで、同期先だけに存在するファイルは削除しない。フォルダ同期は1回の操作として1履歴にまとめ、まとめて復元できるようにする。

## 記録方針

このファイルには、参照元に明記されていなかった実装中の判断、変更、妥協点、仕様解釈、未解決事項、検証上の制約を記録する。

## 判断一覧

### D-001 フォルダ同期対象はフロントエンドで列挙してバックエンドへ渡す

- 種別: 解釈
- タイミング: 実装前
- 参照元に書かれていたこと: 対象ファイルは現在の比較結果から、選択フォルダの `relativePath` 配下かつ `same` 以外のものに限定する。
- 参照元に書かれていなかったこと: 対象抽出を Rust 側で再スキャンするか、React 側の比較結果から列挙するか。
- 判断: React 側で比較結果から同期対象とスキップ対象を列挙し、`sync_folder` にファイル操作リストを渡す。
- 理由: 既存 UI が `CompareSession.results` を正として表示しており、計画も「現在の比較結果から」としているため、再スキャンによる結果ズレを避けられる。
- 代替案: Rust 側でフォルダを再スキャンし直す。
- 影響: API の引数に複数ファイルの操作リストが増える。比較後の外部変更は各ファイルの `beforeHash` 検証で検知する。
- ユーザー確認: 不要

### D-002 フォルダ同期履歴は既存 `SyncHistory` を拡張せず `syncType` で分岐する

- 種別: 技術制約
- タイミング: 実装中
- 参照元に書かれていたこと: フォルダ同期は1回の操作として1履歴にまとめる。
- 参照元に書かれていなかったこと: 履歴 JSON のスキーマを新規フィールドで拡張するか、既存フィールドで表現するか。
- 判断: `SyncHistory` の既存フィールドを維持し、`syncType: "folder"` の場合は `sourcePath` / `targetPath` をフォルダパス、`beforeHash` / `afterHash` をスナップショットツリーの集約ハッシュとして扱う。
- 理由: 既存の `history.json` とファイル同期履歴の読み込み互換性を保ち、UI 変更も最小化できる。
- 代替案: 履歴に `files` 配列を追加して各ファイルのメタデータを保存する。
- 影響: フォルダ同期の個別ファイル一覧は履歴画面には表示しない。復元はスナップショット配下のファイル一覧から実行する。
- ユーザー確認: 不要

### D-003 フォルダ同期エントリの `relativePath` は選択フォルダ基準にする

- 種別: 解釈
- タイミング: 実装中
- 参照元に書かれていたこと: 選択フォルダ配下の対象ファイルをまとめて同期し、復元する。
- 参照元に書かれていなかったこと: 複数ファイルのスナップショット内相対パスを比較ルート基準にするか、選択フォルダ基準にするか。
- 判断: `sync_folder` に渡す各ファイルの `relativePath` は選択フォルダからの相対パスにする。
- 理由: 履歴の `targetPath` は選択フォルダ自体を指すため、復元時に `targetPath + relativePath` で正しいファイルへ戻せる。
- 代替案: `targetPath` を比較ルートにして、エントリを比較ルート基準のまま扱う。
- 影響: バックエンドはフォルダ内の構造だけをスナップショットに保存し、選択フォルダ外へ復元しない。
- ユーザー確認: 不要
